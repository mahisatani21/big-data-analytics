STEP 4: GRAPH TRAVERSALS
============================================================


------------------------------------------------------------
1. GET ALICE'S FOLLOWERS OF FOLLOWERS (2-HOP)
------------------------------------------------------------

Query:

MATCH (alice:User {name:'Alice'})
-[:FOLLOWS]->(follower:User)
-[:FOLLOWS]->(follower2:User)

RETURN 
alice.name AS Alice,
follower.name AS Follower,
follower2.name AS FollowerOfFollower;


Output:

Alice | Bob | Alice

Alice | Bob | Dave

Alice | Carol | Alice

Alice | Carol | Eve



------------------------------------------------------------
2. GET RECOMMENDATIONS FOR ALICE
------------------------------------------------------------

Query:

MATCH (alice:User {name:'Alice'})
-[:FOLLOWS]->(follower:User)
-[:FOLLOWS]->(recommendation:User)

WHERE NOT (alice)-[:FOLLOWS]->(recommendation)
AND recommendation <> alice

RETURN DISTINCT
recommendation.name AS Recommended,
recommendation.city AS City,
recommendation.interests AS Interests;


Output:

Recommended:
Dave

City:
Chicago

Interests:
[tech, gaming]


Recommended:
Eve

City:
NYC

Interests:
[music, fashion]



------------------------------------------------------------
3. GET MUTUAL FOLLOWERS
------------------------------------------------------------

Query:

MATCH (u1:User)-[:FOLLOWS]->(u2:User)
MATCH (u2)-[:FOLLOWS]->(u1)

RETURN
u1.name AS User1,
u2.name AS User2;


Output:

Alice ↔ Bob

Alice ↔ Carol



------------------------------------------------------------
4. FIND SHORTEST PATH FROM ALICE TO GRACE
------------------------------------------------------------

Query:

MATCH path = shortestPath(
(alice:User {name:'Alice'})
-[:FOLLOWS*]-
(grace:User {name:'Grace'})
)

RETURN path;


Output:

Shortest Path:

Alice → Carol → Grace



------------------------------------------------------------
5. FIND ALL PATHS FROM ALICE TO GRACE
(MAXIMUM 4 HOPS)
------------------------------------------------------------

Query:

MATCH path =
(alice:User {name:'Alice'})
-[:FOLLOWS*1..4]-
(grace:User {name:'Grace'})

RETURN path;


Output:

Multiple paths between Alice and Grace displayed.



------------------------------------------------------------
6. NETWORK DISTANCE FROM ALICE TO ALL USERS
------------------------------------------------------------

Query:

MATCH (alice:User {name:'Alice'})

MATCH path =
shortestPath(
(alice)-[:FOLLOWS*]-(other:User)
)

WHERE other <> alice

RETURN 
other.name AS User,
length(path) AS Distance;


Output:

User       Distance

Bob            1

Carol          1

Dave           2

Eve            2

Grace          2

Frank          3



------------------------------------------------------------
7. USERS WITH MUTUAL INTEREST
(SAME CITY AND INTEREST)
------------------------------------------------------------

Query:

MATCH (u1:User),
(u2:User)

WHERE u1 <> u2

AND u1.city = u2.city

AND ANY(
interest IN u1.interests
WHERE interest IN u2.interests
)

RETURN
u1.name,
u2.name,
u1.city,
u1.interests AS CommonInterests;

Alice - Eve

City:
NYC

Common Interest:
music

Find users having the highest number of followers.

MATCH (f:User)-[:FOLLOWS]->(u:User)

3. CLUSTERING COEFFICIENT
(FIND TRIANGLES)
------------------------------------------------------------

Purpose:

Find groups of users where three users are connected.


Query:

MATCH (a:User)-[:FOLLOWS]->(b:User)

MATCH (b)-[:FOLLOWS]->(c:User)

MATCH (a)-[:FOLLOWS]->(c:User)

RETURN 
a.name AS User1,
b.name AS User2,
c.name AS User3;


Output:

User1       User2       User3

Frank       Bob         Dave

Grace       Carol       Eve



Observation:

These relationships represent triangular network
connections.



------------------------------------------------------------
4. RECOMMENDED CONNECTIONS BASED ON COMMON INTERESTS
------------------------------------------------------------

Purpose:

Find possible friends based on similar interests.


Query:

MATCH (u:User),
(friend:User)-[:FOLLOWS]->(u)

WHERE friend <> u

AND ANY(
interest IN u.interests 
WHERE interest IN friend.interests
)

AND NOT (u)-[:FOLLOWS]->(friend)


RETURN

u.name AS User,

friend.name AS PotentialFriend,

[i IN u.interests 
WHERE i IN friend.interests] AS CommonInterests;


Output:


User        PotentialFriend        CommonInterests


Alice       Frank                  [tech]


Eve         Alice                  [music]



Observation:

Alice can be recommended to follow Frank because
they share common interests.

------------------------------------------------------------
7. USER INFLUENCE SCORE
------------------------------------------------------------

Formula:

Influence Score = Number of Followers / Age


Query:


MATCH (f:User)-[:FOLLOWS]->(u:User)

RETURN

u.name,

COUNT(f) AS Followers,

u.age AS Age,

toFloat(COUNT(f))/u.age AS InfluenceScore

ORDER BY InfluenceScore DESC;


Output:


User        Followers     Age      InfluenceScore


Carol          3          25          0.120


Bob            3          32          0.093


Eve            2          27          0.074


Alice          2          28          0.071


Dave           2          30          0.067



Observation:

Carol is the most influential user because she has
the highest followers-to-age ratio.

3. HOW WOULD YOU FIND THE SHORTEST PATH BETWEEN ANY TWO USERS?
------------------------------------------------------------


Answer:

minimum number of relationships between two users.


Example:

(user1:User {name:'Alice'})
-[:FOLLOWS*]-
(user2:User {name:'Grace'})

)

4. WHAT IS THE STRENGTH OF THE GRAPH MODEL FOR SOCIAL NETWORKS?
------------------------------------------------------------


Answer:


Advantages of Graph Model:


1. Efficient relationship traversal.

2. Easy representation of users and connections.

3. Fast shortest path calculations.

4. Supports recommendation systems.

5. Helps identify communities and influential users.

6. Handles highly connected data better than traditional
   relational databases.
